### Document Purpose

This is the operating procedure for the data room (غرفة البيانات والمستندات) — the end-to-end process for intake, naming, upload, review, approval, version control, access request and approval, the update cycle, escalation, and closing/archive. It ties together the index, classification, upload, review, version, and access documents into one runbook. **All figures are illustrative and model-derived.**

---

### Executive Summary

The data room runs on a defined cycle: documents are taken in, named, classified, uploaded, reviewed, and approved; access is requested, approved, expired, and removed; versions are controlled; and the whole is escalated when delayed and archived at close. The Data Room Administrator (DKL) owns the runbook, with content owners, reviewers, and ES accountable at their steps. Every step is logged, and the procedure enforces the rule that classification and version are set before visibility, and that access is NDA-gated and least-privilege.

### Purpose of the Operating Procedure

The procedure makes the data room run consistently and auditably, so that every document is controlled from intake to archive and every access is governed — turning the control documents into a single, repeatable process.

### Process Detail

- **Document intake:** documents received, logged in the index (Doc 01), assigned DR-B#-## and a naming string (ELAN-{DOMAIN}-{TYPE}-v{n}).
- **Document naming rules:** consistent IDs and version suffixes; no overwrites.
- **Upload process:** classify (Doc 02), complete the upload checklist (Doc 03), quality-check, approve, upload.
- **Review process:** route to review types (Doc 04); resolve comments; review-approve.
- **Approval process:** accountable-human adoption per the authority matrix; AI never approves.
- **Version control process:** every change → new version entry (Doc 05); prior versions archived.
- **Access request process:** user requests; NDA executed; role identified.
- **Access approval process:** approved per the access matrix (Doc 06); tags assigned; logged.
- **Update cycle:** periodic review keeps documents current; changes re-versioned and re-reviewed.
- **Escalation process:** delays and blockers (e.g., counsel LD-14) escalate to ES.
- **Closing and archive:** at process close, external access ends; all versions archived; audit trail retained.
